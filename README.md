# 메타 광고 리포트 (템플릿)

메타 Marketing API로 광고 계정 데이터를 매일 자동 수집하고, GitHub Pages 대시보드로 보여주는 저장소 템플릿입니다.
업체명과 데이터는 비어 있습니다. 아래 "새 업체 적용"만 채우면 바로 쓸 수 있습니다.

- **자사몰 계정** (`type: own`): 픽셀 기준 일반 구매 지표
- **협력광고 계정** (`type: collab`): **공유 항목 포함** 구매·장바구니·전환값 (`catalog_segment_actions`, `catalog_segment_value`)

## 새 업체 적용

`accounts.json` 하나만 고치면 됩니다.

| 항목 | 설명 |
|---|---|
| `client` | 업체명. 대시보드 제목과 브라우저 탭에 `<업체명> 메타 광고 리포트`로 표시 (비우면 `메타 광고 리포트`) |
| `accounts[].id` | 광고 계정 ID (`act_` 뺀 숫자) |
| `accounts[].name` | 대시보드 탭에 보일 계정 이름 |
| `accounts[].type` | `own` 자사몰 / `collab` 협력광고 |
| `accounts[].groups` | (선택) 한 계정을 캠페인명으로 나눠 보기. `match`가 캠페인명에 들어 있으면 그 그룹, `match: ""`는 나머지 |
| `accounts[].name_prefix` | (선택) 캠페인명 앞에 붙는 접두어. 행사명을 읽을 때 이 앞부분은 건너뜀 |

예시로 넣어둔 `000000000000000` 등은 가짜 ID이니 실제 계정으로 바꾸고, 쓰지 않는 줄은 지우세요.

## 캠페인명 규칙

- **행사명**: 캠페인명을 `_`로 나눈 첫 토큰 (괄호 부분은 제외)
- **일반/키즈**: 캠페인명에 `일반`·`키즈`가 들어 있으면 그 구분, 없으면 `기타`

## 파일 구성

| 파일 | 역할 |
|---|---|
| `accounts.json` | 업체명과 수집할 광고 계정 목록 |
| `scripts/fetch_meta.py` | 메타 API에서 일자 × 광고세트 단위 데이터를 받아 `data/`에 저장 |
| `.github/workflows/fetch.yml` | 매일 한국시간 오전 6시 47분 자동 실행, 결과를 저장소에 커밋 |
| `index.html` | 대시보드 (기간 선택, 계정 탭, 직전 기간 대비 증감, CSV 다운로드) |
| `data/daily.csv`, `data/daily.json` | 광고세트 일별 성과 (첫 실행 후 자동 생성) |
| `data/ads.json`, `data/creatives.json`, `data/creatives/` | 소재(광고) 일별 성과, 소재 유형, 썸네일 |
| `data/bd_age.json` 외 3개 | 연령·성별·노출위치·기기별 캠페인 성과 |
| `data/products.json` | 카탈로그 제품별 일별 성과 (일자 × 캠페인 × 제품, `product_id` 분석 축) |

`data/` 폴더는 첫 수집 때 자동으로 만들어집니다. 위 파일들은 **암호화된 `.enc`로만 저장소에 올라갑니다**(아래 "비밀번호" 참고).

## 비밀번호

공개 저장소에서도 데이터가 보이지 않도록 `data/` 아래 파일을 전부 암호화해서 올립니다.

- 수집이 끝나면 `scripts/crypt.mjs`가 `data/` 파일을 AES-256-GCM으로 암호화해 `.enc` 파일만 커밋합니다. 원본은 `.gitignore`로 막혀 있어 커밋되지 않습니다.
- 대시보드를 열면 비밀번호를 묻고, 브라우저 안에서 데이터와 소재 썸네일을 풀어서 보여줍니다. 같은 탭에서는 새로고침해도 다시 묻지 않습니다(탭을 닫으면 다시 물어봄).
- 비밀번호는 저장소 Secret `DASHBOARD_PASSWORD`에만 넣습니다. 코드에는 들어 있지 않습니다.
- 암호화되지 않는 것: `index.html`, `accounts.json`(업체명·광고 계정 ID), `data/key.json`(암호화용 salt, 비밀 아님), Actions 실행 로그(행 수만 출력).

**비밀번호 바꾸기**: 기존 `.enc`는 옛 비밀번호로 잠겨 있어서 새 비밀번호로는 못 풉니다.
1. 저장소에서 `data/` 폴더를 통째로 지우고 커밋
2. Secret `DASHBOARD_PASSWORD`를 새 값으로 교체
3. Actions에서 필요한 전체 기간을 다시 수집(백필)

## 세팅 순서

1. **저장소 만들기**: GitHub에서 새 저장소(예: `업체명-meta-report`)를 만들고 이 폴더의 파일을 전부 올립니다. `.github` 폴더도 꼭 함께 올려야 자동 실행이 됩니다.
2. **Secret 등록**: 저장소 → Settings → Secrets and variables → Actions → **New repository secret** 으로 두 개를 등록합니다.
   - `META_ACCESS_TOKEN`: 시스템 사용자 토큰 (`ads_read` 권한, `accounts.json`의 계정 전부 할당)
   - `DASHBOARD_PASSWORD`: 대시보드 비밀번호
3. **(선택) API 버전**: 같은 화면의 Variables 탭에서 `META_API_VERSION`을 추가하면 버전을 바꿀 수 있습니다. 비워두면 `v26.0`.
4. **첫 수집 (과거 데이터 백필)**: Actions 탭 → "메타 데이터 수집" → **Run workflow** → 시작일·종료일 입력 (예: `2026-09-01` ~ `2026-09-30`).
   - 초록색 체크가 뜨면 `data/` 폴더가 생깁니다.
5. **대시보드 공개**: Settings → Pages → Source를 `Deploy from a branch`, Branch를 `main` / `(root)`로 저장합니다. 1~2분 뒤 `https://<깃허브아이디>.github.io/<저장소이름>/`에서 확인할 수 있습니다.

이후에는 매일 아침 최근 7일치를 다시 받아 갱신합니다. 전환은 기여 기간 동안 늦게 잡히므로 최근 일주일 값은 매일 업데이트됩니다.

## 계정 추가/변경

`accounts.json`에 줄을 추가하면 다음 실행부터 반영됩니다. 새 계정은 시스템 사용자에게도 자산 할당을 해줘야 합니다.

## 문제가 생기면

- Actions 실행 로그에서 `API 오류 (code=190)` → 토큰이 잘못됐거나 만료됨. 새 토큰으로 Secret 교체
- `code=200` / `code=10` → 해당 계정이 시스템 사용자에게 할당되지 않았거나 `ads_read` 권한이 없음
- 협력광고 계정의 구매값이 0 → 해당 기간 공유 항목 전환이 없거나, 계정 `type`이 `collab`으로 되어 있는지 확인
- `DASHBOARD_PASSWORD 가 설정되지 않았습니다` → Secret 등록 누락
- `비밀번호가 기존 데이터와 맞지 않습니다` → Secret 값이 바뀜. 위 "비밀번호 바꾸기" 순서대로 진행
- 대시보드에서 "비밀번호가 틀렸습니다" → 입력값이 Secret `DASHBOARD_PASSWORD`와 다름

## 주의

- 공개(Public) 저장소여도 성과 데이터·소재는 비밀번호 없이 볼 수 없습니다. 다만 비밀번호가 짧거나 추측하기 쉬우면(날짜 등) 암호화 파일을 내려받아 대입해 볼 수 있으니, 민감하면 길고 무작위인 비밀번호를 쓰세요.
- 토큰은 코드나 커밋에 절대 넣지 말고 Secrets에만 보관하세요.
